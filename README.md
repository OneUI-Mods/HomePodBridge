# HomePod Bridge

Galaxyのシステムの「メディア出力」からHomePodへ音声を送る、開発中のAndroidアプリとVectorモジュールです。

Apple Musicは変更・フックしません。HomePodをAndroidのメディアルートとして登録し、SystemUIから選択したアプリのメディア音声をAirPlay 2で送ります。マイクは使用しません。

## 対応環境

- Android 16/17、arm64またはx86_64
- rootとVector。モジュールの対象はSystem UIだけです。
- 同じローカルネットワーク上のHomePod／HomePod mini
- HomePod側で同じネットワークからのAirPlay接続を許可していること

## 状態

Galaxy S26 Ultra / Android 17 / One UI 9で、標準のメディア出力とApple Music内のキャスト一覧からの接続・接続維持、端末への切り戻しを確認しています。HomePod miniからの実際の再生も確認済みです。接続直後はミュートから始まり、0〜100%で音量を調整できます。HomePodのステレオペア、パスワードが必要な受信機、IPv6のみのネットワークは未対応です。

Apple Musicのキャスト一覧では、AndroidXに対応した出力先として表示します。音声はAirPlay 2でHomePodへ送ります。Apple Musicは変更・フックしません。他のアプリのCast一覧への対応はアプリ側の実装に依存します。

## 導入

1. 署名済みrelease APKをインストールします。
2. VectorでHomePod Bridgeを有効にし、対象にSystem UIを指定します。
3. GalaxyReloadでSystemUIを再読み込みします。
4. HomePod Bridgeを開き、ローカルネットワークへのアクセスを許可します。
5. 音楽を再生し、Apple Musicのキャスト一覧またはシステムの「メディア出力」からHomePodを選びます。
6. 接続直後はミュートです。アプリまたはシステムの音量スライダーで調整してください。VPNによりWi-Fiへ直接接続できない場合は、HomePod Bridgeのroot権限が必要です。

モジュールが使えない場合は、Android標準の音声共有も利用できます。選択アプリモードではApple Music、端末全体モードではAndroidが許可するメディア・ゲーム音声を対象にします。この場合はシステムの確認画面が表示され、スマートフォンからも音が出る場合があります。

## 音声モードと遅延

開発版0.1.5では、Materialの「接続」「音声」「調整」「診断」タブに整理しています。「音声」でプロファイルを1つ選び、「調整」で保存済みのマニュアル値を確認・編集できます。

- 「標準」は送信前150 ms・標準取り込み10 ms・受信目標1500 msです。
- 「低遅延モード」は送信前0 ms・専用取り込み約0.50 ms・スマホのミキサー周期約2.18 ms・受信目標50 msです。専用経路には対応するroot化端末が必要で、適用を確認できない場合は標準取り込みへ戻ります。
- 「高音質・ロスレス」は44.1 kHz・16 bitステレオを保ち、150 / 10 / 1500 msの余裕ある設定で安定性を優先します。低遅延も同じ音声精度で、ハイレゾ化は行いません。
- 「完全マニュアル」はプリセットによる上書きと自動バッファー調整を止め、個別の数値を使用します。「調整」→「マニュアル設定」で編集し、「適用」で一度だけ再接続します。キャンセルでは変更しません。マニュアル値は別に保存し、他のプロファイルへ切り替えた後も呼び戻せます。

マニュアルでは次の値を指定できます。

| 設定 | 対応範囲 |
|---|---|
| 送信前バッファー | 0〜300 ms |
| 標準経路の取り込み単位 | 2〜40 ms |
| 専用経路のミキサー周期 | 2.18〜21.04 ms。対応する20段階の近い値に丸め、適用予定値を表示 |
| 専用経路の取り込み待ち目標 | 2.18〜18.14 ms（96〜800フレーム） |
| 標準経路のスマホバッファー目標 | 0（無効）、928、1856フレーム |
| 1パケットのフレーム数 | 88または352。標準・代替経路は352 |
| 受信待機の最小・最大と再生時刻のオフセット | 各10〜2000 ms。最大値は最小値以上 |

取り込み経路と、非圧縮PCM／可逆圧縮ALACも同じ画面で選べます。ALACは音声の値を保ち、削減量は内容に依存します。専用経路の読み取り単位は約0.50 ms（22フレーム）の固定値として表示します。

以前の約1.18〜10.50 msという取り込み残量は実測結果です。待ち目標と分けて「診断」に表示し、設定どおりの平均残量になることは保証しません。長いミキサー周期と少ない待ち量の組み合わせでは音切れが増える場合があります。88フレームのHomePod互換性は未確認です。受信目標50 ms未満や個別の受信待機・再生時刻の組み合わせでは、接続できても無音になる場合があります。これらの設定値は実際にスピーカーから音が出るまでの総遅延ではありません。

「選択アプリ」は選択したアプリのメディア音声、「端末全体」は複数アプリの再生音や通知音を転送します。マイクと通話音声は対象外です。Androidの制限により転送できない音声もあります。設定変更時は音量0%で再接続し、アプリの音量範囲は0〜100%です。

端末全体モードで接続中は、端末スピーカー向けのメディア音量操作をHomePodへ連動させます。通常の音量パネルと、三点リーダーで開く詳細パネルに受信機名が表示されます。詳細パネルでは受信機のスライダーでHomePod音量を操作できます。SystemUI側の音量制御APIを使い、共有停止時に元の状態へ戻します。ユーザー補助サービスは使いません。ROMや他の音量制御機能との組み合わせによってはアプリ内のスライダーを利用してください。

## 開発

JDK 21、Android SDK / Build Tools 37、NDK 30.0.14904198、CMake 4.1.2を使用します。

```sh
./gradlew :app:testDebugUnitTest :app:lintRelease :app:assembleRelease
python tools/check_apk.py app/build/outputs/apk/release/app-release-unsigned.apk
```

詳細は[開発記録](docs/development.md)と[配布手順](docs/releasing.md)を参照してください。

## ライセンス

本プロジェクトはApache-2.0です。AirPlay 2送信部分は[airplay2-sender-cpp](https://github.com/akustikrausch/airplay2-sender-cpp)を利用しています。上流コミットはthird_party/airplay2-sender-cpp/UPSTREAM.txtに固定し、著作権・ライセンスを保持しています。Mbed TLSとAppleのALACコーデックは上流のコミットに固定しています。アプリの「オープンソースライセンス」からも確認できます。

AirMusicのソースやAPKを流用していません。Apple、Samsung、AirMusic、Vectorの公式アプリではありません。

「診断」タブで取り込み時刻からの推定経過、システムからアプリへの転送時間、待機音声量、圧縮処理時間、送信時点の余裕を確認できます。Wi-Fiの片道時間・HomePod内部・総遅延は未測定として表示します。容量や目標値を実測遅延として合算しません。
